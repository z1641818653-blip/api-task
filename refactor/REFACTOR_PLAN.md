# Workflow 重构计划

## 稳定基线

- 稳定提交：`8557f2ca795d9a11130bae55640646ac2613e960`
- 稳定分支：`stable/workflow-recovery-2026-07-28`
- 稳定页面：`workflow-recovery.html`
- 重构分支：`refactor/workflow-modularization`

稳定页面在重构完成并通过回归测试前保持不变。

## 重构原则

1. 每次只改变一个边界，不同时修改结构和功能。
2. 节点字段、保存格式、执行顺序和用户界面行为必须保持兼容。
3. 每个阶段完成后执行回归清单。
4. 条件节点、真假分支和多分支路由属于重构完成后的新功能，不混入基础重构。
5. 重构页面使用独立入口，验证完成后再替换稳定页面。

## 阶段

### 阶段 1：机械拆分

- `workflow.html`：页面结构。
- `workflow.css`：全部样式。
- `workflow.js`：现有逻辑，暂不改变函数行为。

### 阶段 2：内部边界

按顺序整理：

1. 数据模型与规范化。
2. 节点查找、增删、移动和复制。
3. 保存、加载、导入、导出和版本历史。
4. 执行校验、执行队列和 DeepSeek 接口。
5. DOM 渲染与事件绑定。

### 阶段 3：行为回归

所有清单通过后，重构版本才允许替换稳定入口。

### 阶段 4：功能扩展

- 条件判定节点。
- 真/假分支。
- 多结果分支路由。
- 条件解析失败时暂停并标红。
